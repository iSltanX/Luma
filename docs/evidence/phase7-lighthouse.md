# Lighthouse — تدقيق الوصول

المرحلة ٧. **خط أساس أول، لا مقارنة.**

الخطة تطلب «مقارنته بنتيجة المرحلة ٤ لكشف أي انحدار تراكمي». ولا
أثر لأي إعداد أو نتيجة Lighthouse من المرحلة ٤ في المستودع — بحثتُ
في الشجرة كلها فلم أجد إلا ذكرًا لاسم الأداة في `PLAN.md` وADR ٠٠٠٧.
فالمقارنة **لا مرجع لها**، وأرقام اليوم تُسجَّل خط أساس أول يُقارَن
به ما بعده. ادّعاء مقارنة بلا طرف ثانٍ أسوأ من الإقرار بغيابه.

## النتائج

| الصفحة | قبل المرحلة ٧ | بعدها |
|---|---|---|
| المحرر | 100 | **100** |
| الإعدادات | 100 | **100** |
| معرض المكونات | 95 | **100** |

## ما سقط قبل المرحلة، وعلاجه

معرض المكونات ٩٥: `label` — «Form elements do not have associated
labels». المصدر عيّنة `صف إعداد` في `src/dev/Gallery.svelte`: مفتاح
بتسمية فارغة، أي `<input type="checkbox">` بلا اسم متاح. المعرض أداة
تطوير لا تُشحن، لكنه **مرجع المكوّنات** — وعيّنةٌ خاطئة فيه تُنسخ.
صار المفتاح يحمل تسمية مع `showLabel={false}`، وهو النمط نفسه الذي
تستعمله شاشة الإعدادات الحقيقية.

## حدود هذه الأرقام

- **Lighthouse يقيس صفحة ويب في متصفح آخر**، وLuma تطبيق macOS في
  WKWebView. نتيجة خضراء منه **لا تعني اجتياز المرحلة** — `PLAN.md`.
- **تدقيق الأداء يسقط بـ`NO_LCP`**: المحرر يفتح على صفحة بيضاء بلا
  محتوى، فلا «أكبر رسم محتوًى» ليُقاس. وذاك هو المنتج لا عيبه — ولذلك
  تُقاس ميزانيات الأداء داخل `Luma.app` وحدها
  ([ADR ٠٠١١](decisions/0011-performance-budgets.md)).
- **ما لا يقيسه أصلًا:** VoiceOver، وقوائم السياق، وتكبير نص النظام،
  وترتيب التركيز الفعلي تحت إعداد «التنقل بلوحة المفاتيح».

## إعادة التشغيل

```bash
npm run dev
npx -y lighthouse@12 http://localhost:5173/ \
  --only-categories=accessibility --chrome-flags="--headless=new --lang=ar"
```

Lighthouse ليس اعتمادية للمشروع ولا يدخل `package.json`: أداة فحص
خارجية تُستدعى عند الحاجة.
